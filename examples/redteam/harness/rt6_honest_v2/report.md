# report.md —— v0.2 对诚实工作是否可用

**pilot**：3 个 toy 任务（T1 代码/计算、T2 推导/证明、T3 复核）、4 名成员（A–D）、4 轮、36 事件。
**日志**：`events.jsonl`；**裁判原始输出**：`score.txt`（`EXIT=0`、`合法性: 通过`、无 violation、1 条 ambiguity）。
**复现**（三条命令都能一字不差重跑）：

```bash
cd "26 summer/DeSci/redteam"
python3 score_v2.py rt6_honest_v2/events.jsonl                    # 10.500 / 10.000；trial 6.000 / 5.500
python3 score_v2.py baseline_v2.jsonl                             # 7.050 / 6.300；trial 5.050 / 4.300
python3 score_v2.py rt6_honest_v2/diagnostics/abstain_probe.jsonl # EXIT=2，abstain 非法
```

**先给结论**：v0.2 **可用**（没有机械障碍，诚实工作能走完全流程），但**对诚实工作的排序能力接近零**。试验级 R_trial 的上界 6.0 被"内容全空的 6 轮日志"（`rt5_attack_v2`）拿到 6.000，我的真实 3 任务日志是 6.000 / 5.500——诚实反而更低，而且低的那 0.5 全部来自一次自愿撤回。

## 逐条判定四个偏好

| 偏好 | 判定 | 一句话理由 |
|---|---|---|
| 1 可靠且可追溯的进展 > 原始产出 | **部分满足** | 结算点/幂等/回溯都真生效，但"可靠"没有任何一项被测量 |
| 2 认真记录的失败有小额正奖励 | **部分满足（方向错）** | 付钱的是"别人 reject 的次数"，不是"失败被记录" |
| 3 返工/无证据/刷分要付代价 | **部分满足（无证据）/ 被破坏（返工、刷分）** | 撤回被罚，错误没被罚；F̃ 可由人制造 |
| 4 记录负担必须进入目标函数 | **被破坏** | H 被移出目标函数，§8 的停止条件不可测量 |

### 1. 可靠进展 > 原始产出：部分满足

成立的部分（实测）：结算真的在 `merge`（`e10` 第二次 merge 不结算 = C1 幂等成立）；`retract` 真的回溯（删掉 `t_e9` 后 trial final 从 5.500 变 6.000 = C3 成立）；fate-sharing 真的按 criterion 权重分。

不成立的部分：**"可靠"和"可追溯"都没有对应的量**。Ṽ 只问 criterion 是否 merge，P̃ 只问 `prov` 字段齐备，F̃ 只问 reject 数。我实测加一个第二位独立 accept checker（在 challenge 之后，合法）：**团队分完全不变（10.500/10.000、6.000/5.500），只是两位 checker 的个体份额被摊薄**（A 0.500→0.450）。也就是说"多一次独立复核"在团队目标函数里的价值精确为 0。而 R_trial = 3Ṽ+2P̃+F̃ 里，Ṽ≤1、P̃≤1、F̃≤1，三项全是合规性度量，所以"全部 criterion 都 merge + prov 字段齐全 + 有 2 次 reject"就正好打满 6.0——rt5 的 artifact 把 `hash` 直接写成字面量 `"0"`、`cmd` 是 `echo 4` 这类单行脚本，配上每轮 2 次自导 reject，打到 6.000/6.000。

### 2. 认真记录的失败有小额正奖励：部分满足，且方向错

F̃ = min(1, **独立 reject 次数**/2)。它奖励的是"否定动作"，不是"失败被记录"：
- 我这次最强的一次诚实失败——**预注册的 P1（k*=3）被自己的输出推翻**（实测 k*=none）——一分没拿。那一轮的 F̃ 来自另一件 artifact 的判据口径 reject；若只有 P1 失败，F̃=0。
- F̃ 与 reject 是否正确无关：v7 那次 reject 的结论上"PASS 是巧合成立的"，理由只是判据口径不符，照样 +0.5；反过来，冤枉一个正确 artifact 的错 reject 也 +0.5。
- 可复现的对照：把 `challenge_e9` 删掉，读数一字不变（10.500/10.000、6.000/5.500）——说明"记录质疑"这件事本身不进入任何目标函数。

### 3. 返工/无证据/刷分要付代价：部分满足（无证据），被破坏（返工、刷分）

- **无证据**这一条真的挡住了东西：三次 reject（e1 转置 bug、e5 饱和误判、e7 判据错位）没有一次能靠填字段过关；`merge` 需要 verified + 独立 checker + ≥40 字 own_words。
- **返工**被罚的是"撤回"，不是"错误"。`credited` 只认每个 criterion 的第一个 merge，所以"撤回 + 重做"（`t_e9` + `e10`）永远不结算，还被打上"规则歧义"标签。**诚实的代价 0.5，不诚实的收益 0.5**：不撤回、把含被推翻 P1 的 artifact 留在记录里 = 6.000；撤回并重做 = 5.500。
- **刷分**：v0.2.1 关掉了逐轮 P̃/F̃ 通胀（我把 `m4` 从 R2 挪到 R3，R_trial 完全不变；RULES §2.1 记录 rt5 逐轮总和 21.0 → trial 6.0），但没关掉 F̃ 的人工通道。我 3 次 reject 都是真的；但"先 produce 一个弱 v1、让同事 reject、再 produce v2"在日志上与我的行为**不可区分**，成本是多一条 produce，收益 +0.5/次（上限 1.0）。
- 我的日志里还有一次"错误被抓住但没有让它进入记录"：A 最初猜"b1=b2 时 P 恒为 1/2"，`t2_checker.py` 直接打脸（0.3914/0.0940），改成 exchangeability 才对。这个失败**只值 0**——它发生在 checker 自己的工具里，没人 reject。

### 4. 记录负担必须进入目标函数：被破坏

v0.2 改动 #5 把 `H/W/U/G/F` 全部移出目标函数，`retrospect` 里的数字字段被显式忽略。后果是 §8 的"记录耗时 ≤ 任务总时间 10–15%"在新系统里**不可测量**：我 4 条 retrospect 写了 6/5/—/9 分钟，裁判器一个都不读。

我这次的实际记录负担（实测字符 + 可数的机械步骤）：自由文本 **3317 字** + 4 条 prediction 字符串 447 字 + **24 个 sha256/跑脚本步骤**。按 25 字/分 + 1 min/步换算 ≈ **157 min**，而任务本体估计 150 min；即使只写 schema 下限（≈590 字），也是 **48 min**。要让 48 min 落在 15% 内，任务总时长必须 ≥320 min。§8 的停止条件在本次 pilot 里**已经被触发**，而系统看不见——这是"记录负担必须进入目标函数"被破坏的直接后果，不是估计误差。（注：单人是 AI 串演，没有真人计时；字符与步骤是实测，分钟数是换算。）

## 诚实团队会不会因为 v0.2 而少做难任务？

**会。** 日志里三条独立证据：

1. **做 3 个任务 ≈ 只做 1 个任务**。把日志切到只剩 R1（`python3 score_v2.py <(sed -n '1,/round 2/p' rt6_honest_v2/events.jsonl)`）→ trial **5.500**；完整 3 任务 → **6.000**。T2（闭式单调性证明 + 反例搜索 + 一次返工）与 T3（stiff sweep + 一次返工）合计只值 **+0.5（8.3%）**。
2. **一次诚实撤回把这 0.5 全部抵消**。完整日志 trial final = **5.500**，与 Q1-only 的 5.500 完全相同。所以"多做两个难任务并诚实修正一次"和"只做一个任务"在最终读数上等价，而前者的工作量是后者的约 2.5 倍。
3. **个体层面更尖锐**：D 做了 T2 全部推导 + 两次脚本修订，final **0.167**；C 做 T3 并撤回自己的 artifact，final **0.083**（撤回让它从 0.167 掉一半）；A 只做检查，final **0.417**，占全部个体分的 50%。做难任务 + 诚实修正的边际个体回报是**负的**。

还有一个更隐蔽的"少做"形态：因为 criterion 冻结不可改，团队的最优策略是**写宽标准**。我在 Q3/c2 里就是这么干的——把锐利预测 P1 降级为 exploratory，只把稳健的 P2 当验收条件（证据：`artifacts/prereg_q3_predictions.txt` 写明"P2 为验收条件"）。这不是少做任务，而是**少下断言**，同样降低信息量；如果 v0.2 的 pilot 继续，这一条会比"少做任务"更普遍。

## 如果只能改一处 schema

**允许被 `retract` 的 criterion 由一个新 artifact 重新结算一次**（`supersedes` 指向被撤回的 id）。

理由（都对应日志里的实测）：
- 直接消掉最尖锐的反向激励：目前"撤回 + 重做"是**永久 0** 且被标成"规则歧义"（`e10`），使得"不撤回"严格优于"撤回"——而撤回/修正正是 v0 §1 的第四个目标、也是偏好 3 唯一要求的行为。改完后我的日志会是 6.000/6.000，诚实不再额外付费。
- **不会重新打开刷分口子**：Ṽ 对每个 criterion 仍被封顶在 `w_c/|T|`、`ΣṼ ≤ 1`；重结算只是把被撤回的那一份还回去，上限仍是"一次完成"，与现在完全一致。`retract` 仍使 as-of 保留、final 掉分，C3 的回溯不被破坏；每 criterion 最多重结算一次，也不能靠"merge-retract-merge"循环叠加。
- 成本极低：一个 `supersedes` 字段 + 一条覆盖规则。

**备选（我不选，但值得记录）**：给 `prediction` 强制预注册锚点（`prereg_hash` + 要求 artifact 的行序早于同 task 的测试 artifact）。它能堵掉 postdiction，但我的数据显示当前最痛的并不是"别人能后验编预测"，而是"我改对了反而更亏"；而且 R_trial 已经饱和（空内容也能到 6.0），再提高证据门槛不会改变排序，只会再增加一轮记录负担。

## 边界与不确定

- **失败分支的构造方式**：三次 reject 的数值全部来自真实运行的脚本（`artifacts/` 全部可重跑，输出在 `artifacts/out/`），但"先错后修"的顺序是我按 pilot 要求设计的场景，不是自然发生的意外。`t1_v1_transpose.py`、`t2_search_v1.py`、`t3_stiff_v1.py` 三个失败版本都原样保留，未删除。
- **预注册是真的**：`prereg_q3_predictions.txt` 写在任何 k-sweep 之前；**P1 被推翻是我没有预料到的**（我猜 k*=3，实测 k*=none）——这本身是"没有 postdiction"的最好证据，一个后验编造的人会写 k*=none。
- **撤回是一个可辩护但非唯一的选择**：我为了"不把已被自己推翻的断言留在 merge 记录里"而撤回；选择不撤回同样诚实（verify.evidence 已经记录了 P1 失败），且分数是 6.000。**v0.2 没有"收窄/降级"这个动作**，只能在"全撤回"和"什么都不做"之间选——这本身是 friction。
- **独立性有限**：T3 复用了 T1 的解算器（`t3_stiff.py` import `t1_stationary`），两条读数并非完全独立，只是扫描逻辑不同；这一点写进了 `m5` 的局限。
- **时间数字是换算不是实测**：单人由 AI 串演 A–D，没有真人计时；真人体 pilot 必须实测 `minutes`，否则 §8 的判断只能靠猜。
- **裁判在 pilot 期间被改过**：`score_v2.py` 18→21 KB、`RULES_v0.2.md` 7.0→8.3 KB（v0.2.1 试验级口径）。`score.txt` 是 12:26 之后版本的输出（sha256 `2fe75ade…0e07`）；逐轮 10.500/10.000 与 trial 6.000/5.500 都属于该版本。
