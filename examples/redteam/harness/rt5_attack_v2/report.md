## 2. C1–C4 判定

### C1（增加 criterion / artifact 数量不能抬高 R_t）——**部分成立**

- **成立的一半**：`Σw=1` + `Ṽ` 按 `|T|` 归一 + 幂等，使单个 task 的 V 质量 ≤1；同一 criterion 的第二个 merge 不计分。`c1_merge_twice`：2 个 artifact、2 次 merge，仍 `5.000`，只多一条歧义提示【裁】。
- **被推翻的一半**：同一 criterion 再加一个 artifact、给它 2 次 reject → `c1_base 5.000` → `c1_extra_artifact 6.000`（两口径同涨）【裁】。原因是 F̃ 的计数（`score_v2.py:291-294`）遍历**全部** events 的 verifiers，不受 `credited` 幂等表约束。所以"artifact 数量"确实能抬高 R_t。
- **对 `Σ_t R_t` 完全不成立**：每个 criterion 可占一轮 merge → P̃/F̃ 每轮再生。6 criterion/6 轮 = 21.000；12 criterion/12 轮 = 39.000【裁】。C1 只约束 `R_t` 的取值域，不约束轮数求和；而"拆任务/微事件"在 v0.2 里正是靠 criterion 数量变成轮数。
- **C1(a) 的取值域成立但已被绕开**：criterion 数量本身不加分，可是加了 criterion 就必须从难项挪权重，`padded`（难项 w=0.01 + 4 个等价琐碎项 w=0.2475）把同一份零工作从 `0.000` 抬到 `5.970`（`hard_only` vs `padded`）【裁】。这不是数量效应，是权重自选——但 C1 声称保护的东西在行为层面已经失效。

### C2（自报 H/W/U/G/F 与 p_e 不影响任何分数）——**成立（窄真）**

- 配对日志 `c2_dirty`（H=0,W=0,U=0,G=0,F=12,p_e=0.99,ai_share=1.0）与 `c2_honest`（H=6,W=3,U=2,G=4,F=0,p_e=0.02,ai_share=0.0）只差这些字段：逐轮 `5.000/5.000`，试验级 `5.000/5.000`，个体贡献也相同【裁】。
- 主日志把 `F=12, H=0.01` 塞进 retrospect：只触发 5 条歧义提示，R 不变（21.000 / 6.000）【裁】。rt1 的"自报 F=12 直接加分"与"一行 retrospect R=99.999"确已堵死。
- **窄在哪**：同属自报的 `w`（权重）、`prov` 三字段齐备、`reject` 次数仍然直接决定分数。v0.2 移走的是**诚实的成本项**（H/W/U/G），留下的自报项全部是**收益项**。C2 成立，但不构成任何安全性。

### C3（先 merge 后 retract，R_final 会下降）——**部分成立**

- `c3_retract_all`：主日志 + 从未贡献的 D 在第 7 轮一次性撤回全部 6 件 → 逐轮 `21.000→18.000`（只掉 3.0 = 14%）；试验级 `6.000→3.000`（掉 50%）【裁】。
- **只有 V 被回溯**：P̃_trial=1.000、F̃_trial=1.000 在撤回后不变，每轮 `R_final` 仍 `3.000`（=2+1）。**把全部产出撤回，仍留一半上界**；`retract_repair` 同构（5.000→3.500）【裁】。
- **撤回没有权限检查**：`_op_retract` 不看 actor。D 撤回 A 的 6 件后，A/B 的 final 个体分 `0.500→0.000`，D 自己 0 分且**没有任何代价**（`produce=12, retract=6`，D 未产出一件）【裁+代码】。
- `R_asof` 仍是 21.000：对外汇报用 asof 就完全不用承担回溯。所以"会下降"成立，"回溯生效"只对 V 生效，而且是**可选口径**。

### C4（prov 字段不齐只会让 P̃ 变低，不会成为可刷的加分项）——**被推翻**

- **代码证明**：`_op_produce` 的合法性检查（`score_v2.py:150-165`）——rerun/counterexample 类必须有 `hash`+`cmd`；prediction 类必须有 `prediction`+`threshold`；`prov.sources` 非空字符串列表；`ai_share∈[0,1]`；`version` 为 int——**严格蕴含** `_prov_ok`（`:173-182`）为真。故每个登记成功的 artifact 都 `prov_ok=True`，**任何合法日志里 P̃_t ≡ 1（该轮有 merge 时）、P̃_trial ≡ 1**。20 条日志（18 探针 + 主日志 + `baseline_v2`）实测：P̃ 只取 `0.000`/`1.000`，0 只出现在"该轮无 merge"【裁+证】。
- 于是"字段不齐只会让 P̃ 变低"是**空真**：字段不齐的 produce 直接判**非法**，整条事件消失（`appendix_illegal_prov`：缺 `version` → 3 条非法、`EXIT=2`、R=0）【裁】。真实行为不是"P̃ 变低"，而是"事件不存在"。
- "不会成为可刷的加分项"也被推翻：P̃ 不是 gate，是**加性常数 +2**（占上界 1/3）。v0 要填 `p_e=1.0`；v0.2 要填三个**本来就必须填**的字段；v0.2.1 直接白送。**provenance 改造的实际效果 = 把可刷项变成恒等项**；`ai_share=1.0`（100% AI）也不减一分。

## 3. 新机制 H1–H10

**H1 轮数农场（v0.2）→ v0.2.1 把它压成"一轮饱和"。** P̃（+2/轮）、F̃（+1/轮）是逐轮量，Ṽ 是全局总量（Σ_t Ṽ_t ≤ 1）。把同一批 criterion 摊到 K 轮：`R ≈ 3K+3`。6 轮 21.000，12 轮 39.000【裁】。v0.2.1 把总和封到 6.000，但**代价是"满分不再需要 6 轮"**：1 轮 6.000（H2/H3 合用）【裁】。

**H2 content-free artifact + 假 hash + 空 sources。** 6 条 criterion 语义完全等价（都只断言 `stdout == 4`），`cmd ∈ {print(2+2), print(1+1+1+1), echo 4, print(4*1), print(len([1,2,3,4])), echo $((2+2))}`，`hash="0"`，`own_hash="0"`，`prov.sources=["x"]`。裁判不比较两个 hash、不比对 cmd、不复跑、不查 sources 内容。结果 V=1、P̃=1、R_trial=6.000【裁】【法】。"用什么工具产生"在这个接口上等于自报字符串。
**criterion 冗余是否被禁止？不禁止。** 接口强制"一个 artifact 对应一个 criterion"，所以"一个 artifact 满足 3 个等价 criterion"必须写成 3 个 produce（同一 `cmd`、同一 `hash`）；裁判不做任何重复检测（`events_per_criterion` 只是诊断），3 条全部计分。因此**单轮上限 6.0/6.0 可以完全由同一个琐碎事实复制出来**；逐轮口径下还能复制到 39.0。

**H3 F̃ 制造（无去重、无一致性）。** `F̃_trial = min(1, 全试验 reject 数/2)`，reject 可来自同一 actor、同一 target、同一轮：`trial_max_1round` 里 B 对同一 artifact 连打 2 个 reject（"输出 5"）后立刻 accept（"输出 4"），`F̃=1.000`，`R_trial=6.000`【法】【裁】。真实失败不需要存在；`n_reject` 只是计数，`events_per_criterion=1.0` 也不会报警。

**H4 P̃ 是恒等于 1 的死项。** 见 C4。结构后果：`R_trial = 3Ṽ + 2 + F̃`，其中 `+2` 与日志内容无关；`+1` 只需两条 20 字符的 reject。**3.0/6.0 是任何合法日志的地板**；`baseline_v2` 的 4.300 里 2.500（58%）也是这个地板【算】。

**H5 标准/权重自选 + prediction 自证。** proposer = producer。`hard_only`（唯一难 criterion w=1.0，两周未解）`0.000`【裁】；`padded`（同一难任务，难项 w=0.01，4 个等价琐碎项共 w=0.99）`5.970`【裁】。`prediction` 类的 `prediction`/`threshold` 是自由字符串，裁判不做数值比较、不检查"预测是否写在观测之前"：照抄实测值即 `5.000`（`prediction_selfgraded`）【裁】。

**H6 retract 三重失效。** (i) 只扣 V，P̃/F̃ 免疫（C3）；(ii) 无 actor 授权，任何人可撤回任何人的已结算件，零代价（`c3_retract_all`）；(iii) 无修复路径：同一 task 内撤回后该 criterion 永久失去 V；开新 task 补做则 `|T|` 翻倍、历史 V 腰斩（`retract_repair`：逐轮 7.000→5.500，试验级 5.000→3.500）【裁】。**诚实纠错比不纠错更亏**，而"prov+reject 农场"根本不经过 V，所以撤回伤不到农场。

**H7 checker 份额被 sybil 稀释/窃取。** `verify` 只允许在 `draft`/`disputed` 上执行，因此第二个 accept 必须先用 challenge 把状态推回 `disputed`；`share = 0.5/len(set(accept actors))`，无独立性检查、无人数上限。`checker_split_sybil`：B 拿到 0.5 后，C、D 各 challenge 一次 + accept 一次（都明写"没有复跑"），B 的份额 `0.500→0.167`，C/D 零工作各得 `0.167`；队伍 R 不变（`5.000`）【法】【裁】。这是一个**队伍总分看不见的个体分盗窃**，也是 challenge"不计分"的真实用途。

**H8 challenge 无牙 + merge 自动"解决"争议。** `challenge` 对已 merge 事件的实质质疑：`challenge` 探针 R 逐轮 `7.000`/试验级 `5.000`，与无质疑版本逐字相同；被质疑且**未解决**的 artifact 在 `R_final` 里照常计分（只有 `retracted` 被排除）【裁】。`_op_merge` 还会把该 target 所有未解决 challenge 直接标成 `resolved`（`score_v2.py:239-241`），而 `resolved` 不进入任何分数或诊断。所以：反对意见零收益、零效果、零成本——**供给不足与纯干扰同时成立**。

**H9 |T| 稀释 = 惩罚野心；`R_asof` 不是 as-of。** 分母是**最终**任务数。主日志第 7 轮 propose 一个永远不做的 task → 逐轮 `21.000→19.500`，试验级 `6.000→4.500`（−25%），个体 `0.500→0.250`【裁】。同一机制让 `R_asof` 不可信：第 1 轮已"落袋"的 `3.510` 事后变成 `3.255`（`events.jsonl` vs `asof_late_task` 第 1 行）【裁】。**提出一个难问题会追溯扣掉你已有分数的 1/|T|**——与"提出好问题"的系统目标反向。反过来，"提很多容易 task 并全部完成"不赚：`Ṽ = (Σ_task 1)/|T| = 1`，与只提 1 个 task 完全相同，只是多做了 artifact。所以最优策略不是"多提"，而是"**1 个 task + 若干等价 criterion**"（H2）。

**H10 merge/propose 角色 0 分 → free-riding；fate-sharing 只覆盖 artifact 层。** `baseline_v2` 里 C 做了 2 次 merge（`m1`、`m2`），个体贡献表里**根本没有 C**（0.000）【裁】。`challenge` 探针里 D 写了 20+20 字符的实质质疑得 0，E 写 20 字符 accept 得 0.250【裁】。攻击者用 2 人即可吃满（A 产、B 既 accept 又 merge，各 0.500），"独立复核"退化为 producer ≠ others 一层；merge 角色由同时是 checker 的人顺带承担，纯整合者被系统性剥削。
**B 完全不看时，代价是什么？** 主日志里 B 一个人完成了 12 次 verify + 6 次 merge，总共只写了 18 条 ~30 字符的字符串（其中 12 条自带 `own_hash="0"`），没有任何复跑证据被校验，拿 0.500【裁】。B 的**唯一**代价是"若有人撤回则 final 归零"：`c3_retract_all` 里 A/B 的 final 都是 0.000【裁】。所以答案是：**代价接近于零**——撤回要有人发起、发起者零成本零收益、且 asof 表里 0.500 照样打印；**"撤回时两人一起扣分"不足以威慑**，因为它只作用在可选的 final 口径、只作用在 V 项，而且它要求有人愿意做那个免费的撤回者。

## 6. v0.2/v0.2.1 相比 v0 真正改善了什么、没有改善什么

**真正改善（都能用数字兑现）**
1. 结算点从 `verify` 移到 `merge`：未 merge 的 verified 不计分。主日志 6 个被 reject 的坏工件（共 12 个 produce）贡献 0；rt1 的"verify 即落袋"被堵【裁】。
2. V 从"事件数"改为"预注册加权标准完成比例"：`scale_k12` 有 24 个 produce 仍只 `Ṽ=1`；v0 下 24 个事件会线性加分【裁】。拆微事件本身不再换分。
3. 自报 `H/W/U/G/F`、`p_e` 真的出局（C2 成立）：rt1/rt2 的"F=12""retrospect 一行 99.999"被堵死【裁】。
4. 撤回有回溯（部分）：`R_final` 会掉；rt1 的"先 verified 后 retract 分数不变"被堵住，但只对 V 生效（C3）。
5. challenge 不再 +2：v0 的 challenge 农场被堵。
6. 上界真的存在了：v0.2.1 的 `R_trial ∈ [0,6]`，12 轮不再膨胀（39.000 → 5.999）【裁】。

**没有改善（甚至变差）**
1. **无界性只换了变量名**：v0 = 事件数，v0.2 = 轮数，v0.2.1 = 自写标准完成率。三次都是"自报输入 → 线性加分"，没有一次把分数绑到裁判能独立重算的量上。
2. **内容-free 仍然满分，而且更便宜**：v0.2.1 只要 6 个事件、5.5 分钟就到上界（v0.2 要 6 轮 29.5 分钟才 21.0）。修 bug 的同时把"打满上界"的成本压到 1/5【裁/假】。
3. **惩罚项被删除而不是被测量**：v0 有 `−2W−5U−5G−3·false_check`（虽自报），v0.2/0.2.1 一个负项都没有 → **R ≥ 0 恒成立，gaming 永远不亏**。自造失败、重复提交、互抬分数全部零代价。这是净损失，不是改进。
4. **provenance 从"可刷"变成"恒定"**：v0 的 `p_e` 至少是一个（可自报的）连续量；v0.2 的 P̃ 对合法日志恒等于 1（C4），鉴别力从"可以填满"变成"本来就是满的"。
5. **个体层 free-riding 未变**：merge/propose 仍 0 分（H10），`baseline_v2` 的 C 两次 merge 得 0.000；fate-sharing 只把生产者和 checker 绑在一起，不覆盖整合者与质疑者。
6. **"争议未解决不得 merge"没实现**：challenge 无牙、可被任意 accept 覆盖、merge 还会把未解决 challenge 自动标成 resolved（H8）。
7. **3.0/6.0 是白送地板**：官方分数的一半与日志内容无关（H4）。

## 7. 如果只能再加一条规则

**现状诊断**：v0.2.1 已经正确修掉"轮数无界"。残余最大面不是轮数，而是 **3.0 地板 + 另外 3.0 由 proposer 自写的 criterion 定价**。所以这一条规则应该加在 criterion 上，而不是再加在 R 的求和方式上。

**建议规则（one rule）：criterion 级外部难度权重 `d_c`。**

```
propose 时每条 criterion 必须带 "d": d_c ∈ (0,1]，由不在该 task 生产者集合内的成员 countersign；
  R_trial' = 3·(1/|T|)·Σ_task Σ_c d_c·w_c·1[c 已 merge 且未撤回] + 2·P̃ + F̃
```

**为什么选它（反事实数字，【算】自【裁】的 Ṽ/P̃/F̃）**
| 日志 | 现行 R_trial | 加 `d_c` 后（trivial 项 d=0.05，真项 d=1） |
|---|---:|---:|
| `trial_max_1round`（零工作） | 6.000 | **3.150** |
| `events.jsonl`（零工作） | 6.000 | **3.150** |
| `padded`（难项 0.01 + 琐碎 0.99） | 5.970 | **3.179** |
| `baseline_v2`（真 criterion） | 4.300 | **4.300** |
| `honest_hard`（真 criterion，2 条未解） | 4.450 | **4.450** |
| `hard_only`（难项未解） | 0.000 | **0.000** |

**排序反转**：现在 6.000（零工作）> 4.450（真工作）；加 `d_c` 后 3.150 < 4.300 ≈ 4.450。这是本次所有候选规则里唯一能反转排序的。

**为什么不选"把 P̃/F̃ 改成乘性 gate"**：那只能把地板 3.0 变成 0；攻击仍靠 V（自写标准）拿 3.0，诚实组 V=1.8 → 4.000 vs 2.300，**排序不变**【算】。所以 gate 化不是重点，给 V 定价才是。

**代价与失败模式（诚实写）**：`d_c` 是判断，不是测量；同伙 countersign 全部 `d=1` 就退化为 v0.2.1。因此必须三条同时成立：(i) 签署者在生产者集合之外；(ii) `d` 在 **produce 之前**登记（防事后追认）；(iii) `d` 进入审计日志，与最终 `retract/challenge` 记录一起复盘。这条规则不能替代"真实复跑"，它只保证**自写标准的完成率不再等于分数**。剩下的 3.0 地板还需要另一条规则（把 P̃/F̃ 变成乘性 gate），但题目只允许加一条。

## 8. scorer bug / 规则歧义（只报告，未改）

1. **P̃ 是死项**（C4 的代码证明）：`_op_produce` 的合法性检查严格蕴含 `_prov_ok`；`_prov_ok` 是永远为真的分支。
2. **`R_trial` 由四舍五入后的分轮值相加**：`v_asof = Σ round(Vtilde_asof, 4)`（`score_v2.py:337-338`），每轮丢 ≤5e-5，K 轮线性累计。`scale_k12` 真实 Ṽ=0.9999996，裁判给 `5.999` 而非 `6.000`（12 轮 × 3.3e-5）【裁】。**交叉验证**：Lead 的 `verify_all.py` 用同一构造复制到 n 轮，得到 `n=2 → trial=6.000`、`n=6 → 6.001`、`n=12 → 5.999`【裁】——即"上界 6.0"被舍入**突破到 6.001**，且 trial 分并非严格与轮数无关（±0.001）。改法：累加未舍入值，只在显示时舍入。
3. **`R_asof` 不是 as-of**：`_score` 用最终 `len(self.tasks)` 重算每一轮（`:283`）。第 7 轮多一个 propose，第 1 轮 `3.510→3.255`，`R_trial 6.000→4.500`【裁】。"两套读数"里的 asof 读数在设计上就不可信。
4. **challenge 是第二个 accept 的必要跳板**：`verify` 只允许在 `draft`/`disputed` 上执行（`:190`），所以 sybil 稀释必须借 challenge 完成；`share=0.5/len(set(accept actors))`（`:311-315`）无独立性/上限约束。
5. **merge 自动把未解决 challenge 标成 `resolved`**（`:239-241`），而 `resolved` 不进入任何分数或诊断。
6. **权重容差从 1e-6 放宽到 1e-3**（12:24 同步改动，`:133`）：`Σw` 可到 1.0009 → `Ṽ` 可 >1（上限 6.0027）。收益可忽略，但"归一"不再是硬约束。
7. **规则歧义**：`retrospect` 带 `H/W/U/G/F` 只提示歧义；`challenge` 对已 `verified`/已 `merge` 事件合法（v0 草案的"争议未解决不得 merge"在 v0.2 被删除）。

**交叉核对**：Lead 的 `python3 verify_all.py` 对同一 `events.jsonl` 给出 `逐轮和=21.000 / trial=6.000`，并独立复现了"3 个琐碎任务""0.99/0.01 权重劫持""1 件琐碎 artifact + 2 次垃圾 reject 拉满 F̃"三种构造；它的 n=6 复制给出 `trial=6.001`，正好复现 §8.2 的舍入 bug。我的 18 条探针是对这些机制的逐条最小化与边界确认（例如 C1 的 F̃ 通道、C4 的 P̃ 恒等性、H7 的份额稀释），不是同一构造的重复。

**推测（未演示，明确标注）**
- `d_c` 规则的反转数字是手算，没有实现进裁判；同伙签字会使它退化（§7）。
- 真实部署里"裁判复跑 hash"能挡住假 hash，但**挡不住 content-free**：`print(2+2)` 真的能复现 4。所以复跑不是解药，标准定价才是。
- 多团队共享积分榜时，`|T|` 稀释可被用来打压对手（本模拟是单团队日志，未演示）。
- 未测试：同一 task 二次 propose（规则已判非法）、跨文件拼接日志、`round` 极端值。

**一句话**：v0.2 把"事件数套利"换成了"轮数套利"，v0.2.1 把"轮数套利"换成了"自写标准的完成率 + 3 分地板"。三次修订都在改**求和方式**，没有一次把分数绑到**裁判能独立重算、且团队不能自写**的量上；所以每一次的满分都仍然是 6 个事件。
